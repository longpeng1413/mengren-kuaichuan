## 设计

### 语音消息（不改协议）

- 语音就是普通文件，走原有的局域网/配对/公网中转文件传输。格式：16 kHz、单声道、16 位 WAV（识别引擎能直接读，约 1.9 MB/分钟），最长 60 秒（`maximumVoiceSeconds`）。
- 文件名带时长：`语音消息_YYYYMMDD_HHMMSS_<秒>s.wav`（`voice/voice_store.dart` 的 `voiceFileName / voiceSecondsFromName / isVoiceFileName`，接收端改名加的“ (1)”也认）。旧版收到的就是一个可播放的 WAV 文件。
- 录音：`voice/voice_audio.dart` 的 `PlatformVoiceRecorder`（插件 `record` 7.1，`AudioEncoder.wav`，开降噪和自动增益）。播放：`VoicePlayer`（插件 `audioplayers` 6.8，同一时间只播一条，`playingId` 驱动气泡图标）。
- 存储：`VoiceStore`，Windows/Android 都在 `getApplicationSupportDirectory()/voice_messages`。录音中的文件以 `.recording` 结尾，结束后改名为带时长的正式名。收到的语音在 `app.dart _finalizeCompletedTransfer` 里被识别出来，交给 `_finalizeVoiceMessage` 移入该目录（不进下载文件夹、不弹“已收到”提示），消息 `isCache=true`。发出的语音同样 `isCache=true`（`_isAppCacheFile`），删除消息/清空会话会一起删除文件（有其他消息引用时保留）。
- 清理：每次启动 `VoiceStore.cleanup()` 删除 `.recording` 残留、超过 30 天的文件，再按时间从旧到新删到总量 ≤ 500 MB；日志 `voice_store_cleaned`。设置 → 常规 → “语音消息”显示大小、可清空。文件被清理后气泡显示“N″ 已过期”。
- 聊天页（`chat/chat_page.dart`）：输入框左侧 `_MicButton`。**按住**（`onLongPressStart`）开始录语音消息，上滑超过 60 像素变为“松开取消”，松开（`onLongPressEnd`）结束：不到 1 秒提示“说话时间太短”，否则 `finishRecording` 后走 `_sendFiles([path])`（离线排队、进度、停止都沿用）。60 秒自动发送。录音时 `_RecordingBar` 显示计时和提示。语音气泡 `_VoiceContent`（“▶ 12″”，宽度随时长变化），点一下播放/停止。引用摘要为“[语音] 12″”。
- 权限：Android Manifest 新增 `RECORD_AUDIO`，`record` 插件在第一次录音时请求。Windows 麦克风被隐私设置禁用时提示去“隐私和安全性 → 麦克风”打开。

### 语音转文字与语音输入（离线）

- 引擎：`sherpa_onnx` 2.0.1（k2-fsa，Apache-2.0）+ SenseVoice Small int8（FunAudioLLM，FunASR 模型许可），`useInverseTextNormalization: true`（数字写成阿拉伯数字、带标点）。实测对比：k2-fsa 发布的 `…-int8-2025-09-09` 是由粤语专用模型 WSYue 转换而来，普通话漏字、英文错误多；**用官方原版 `…-int8-2024-07-17`**。
- 模型托管：本仓库 GitHub 预发布 `asr-model-sensevoice-2024-07-17`（`--prerelease --latest=false`，一键更新只读 `releases/latest`，不会把它当成软件新版本）。两个文件：`model.int8.onnx`（239,233,841 字节，SHA-256 `c71f0ce0…2cd51`）、`tokens.txt`（315,894 字节，`f449eb28…1a1dc`），哈希写死在 `voice/speech_service.dart` 的 `SpeechModel.defaultFiles`。上传时 239 MB 文件经本机 Clash 代理连续被断开，改为不走代理（`env -u HTTPS_PROXY …`）直接上传成功。
- 下载：`SpeechModel.download`，用 `AppUpdateService.createDownloadClient()`（与一键更新相同的系统代理逻辑）。写入 `<名字>.part`，再次下载时带 `Range` 从断点继续，完成后核对大小和 SHA-256，不一致则删除并报错；全部完成写 `.verified` 标记。30 秒无数据报错。位置 `getApplicationSupportDirectory()/asr_model/sensevoice-int8-2024-07-17/`。启动时 `SpeechModel.cleanup()` 删除超过 7 天的 `.part` 和旧版本目录。设置 → 常规 → “语音识别模型”显示状态与大小，可下载/删除。日志 `speech_model_download_*`。
- 首次使用：`voice/speech_download_dialog.dart` 的 `ensureSpeechModel` 先说明（大小、离线、可能需要代理、可断点续传）再显示进度对话框（速度、取消、失败后重试）。
- 识别：`SpeechRecognizerService` 在后台 isolate 里运行（`_speechWorker`），模型加载一次常驻，空闲 3 分钟释放；请求串行排队。线程数 = CPU 核数（1～4）。实测（本机）：首次 1.1 秒（含加载 239 MB 模型），之后 0.13 秒；5.6 秒中文样例输出“开饭时间早上9点至下午5点。”。
- **Windows 运行库坑**：Windows 11 的 System32 自带旧版 `onnxruntime.dll`（ORT 1.17），sherpa 需要新版（API 28）。程序目录在 DLL 搜索顺序里排第一，所以正式程序没问题；但 worker 仍在 Windows 上先从程序目录（或测试指定的 `libraryDirectory`）显式加载 `onnxruntime.dll`。`flutter_tester` 不在程序目录运行，测试里必须传 `libraryDirectory`。
- 转文字：长按语音 → “转文字”（没有文字时）/“隐藏文字”。结果存进 `ChatMessage.transcript`（`app.dart _setTranscript` → `_updateChatMessage`），显示在气泡下方 `_TranscriptBlock`（可选择复制）；识别不出文字时存“（没有识别出文字）”。
- 语音输入：**点一下**麦克风开始听写（先 `ensureSpeechModel`），再点一下结束 → 识别 → 插入输入框光标处并聚焦；听写用的录音识别后立即删除。

## v1.11.1 补丁（2026-11-09）

- 版本 `1.11.1+37`。用户实测 v1.11.0：电脑端点语音报“无法开始录音：PlatformException(Record, null, 指定的对象或值不存在。, null)”。
- **原因**：`record_windows` 用 `MFCreateSinkWriterFromURL(path, NULL, NULL, …)` 创建录音文件，Media Foundation 按扩展名选文件格式；v1.11.0 的录音中文件名是 `rec_<时间>.wav.recording`，扩展名 `.recording` 不认识，返回 `0xC00D36D5`（MF_E_NOT_FOUND，“指定的对象或值不存在”）。用临时 C++ 程序对比确认：`rec_1.wav.recording` 返回 0xC00D36D5，`recording_1.wav` 成功。本机有 USB 摄像头麦克风且麦克风隐私设置允许，排除了设备原因。单元测试用的是假录音器，所以没发现。
- **修复**：`VoiceStore.newRecordingFile` 改为 `recording_<时间>.wav`（`recordingPrefix`），启动清理按前缀识别录音残留，并兼容删除 v1.11.0 留下的 `*.recording`。`chat_page.dart` 的错误说明在 `PlatformException.message` 为空时显示 `details`，不再显示整串异常。
- **实机验证**：临时加入 SDK 自带的 `integration_test`，用 `flutter test integration_test/… -d windows` 在真实 Windows 程序里用本机麦克风录 2 秒（录音前按用户授权关闭了正在运行的猛人快传，测完重新打开）：生成 `语音消息_…_2s.wav`（标准 RIFF/WAVE），识别引擎 `readWave` 读出 16 kHz、超过 1 秒的采样。测试文件和临时依赖已撤销。
- 新增断言：录音中文件必须以 `.wav` 结尾；清理同时删除新旧两种录音残留。应用测试仍为 125 项。
- **只发布 Windows**（用户要求：手机端没改就不发）。GitHub `v1.11.1` 只带 ZIP 和清单；手机自动检查只在找到本平台安装包时才提示，所以不受影响，手动检查会提示“暂时没有本平台的安装包”。Android 最新安装包仍是 v1.11.0；下次发版要带上 APK，版本号会从 37 之后继续。
