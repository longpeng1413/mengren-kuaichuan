# 架构说明（v1.11.0）

本文描述当前代码的实际做法。早期设想但没有实现的部分（设备签名密钥、分块上传与断点续传接口）已删除，见文末“未实现”。

## 1. 总体

- Flutter 一套代码同时构建 Android 与 Windows，主要业务在 `app/lib/src/app.dart`。
- 局域网内设备之间直接通信，不需要服务器；可选的公网中转服务由用户自己部署（`relay_server/`）。
- 端口：UDP 53317（发现）、TCP 53318（HTTP 文件/消息 和 配对 WebSocket）。
- 协议版本：局域网发现报文 `version: 1`，配对通道 2，公网中转 3。所有参与传输的设备应使用相同协议版本。

## 2. 设备身份

首次启动生成并保存在本机（SharedPreferences）：

- `deviceId`：随机 ID，不因改名或换网而变化，用来合并同一设备的 IP 变化。
- `displayName`：用户可修改，允许重名；界面上必要时附加短 ID。
- `platform`：`android` 或 `windows`。

没有设备签名密钥：局域网直连时，发送方的设备 ID 是它自己报的。所以“只限连接过的设备”自动接收在不可信网络上可以被冒充（设置和帮助里提醒公共 Wi-Fi 选“每次都询问”）；二维码配对通道有配对码校验，公网中转有家庭口令加密，不受影响。

## 3. 局域网发现（`discovery/`）

- 每台设备在所有有效网卡上监听 UDP 53317，每 2 秒广播一次公告；7 秒没收到就判为离线。
- 公告是 JSON：`version`、`type: "announce"`、`deviceId`、`displayName`、`platform`、`port`。
- 同时发送全局广播和每个网段的定向广播；Windows 用系统给出的真实网络前缀计算广播地址（支持 `/23` 等）。对已知设备额外单播保活，并对收到的公告限频回应。
- 网卡变化时重建套接字并重新广播；按 `deviceId` 合并结果，不产生重复设备。
- Windows 隐藏到托盘后仍持续发现；Android 切到后台时暂停（开启“后台持续接收”且前台服务启动成功时除外）。接收数据时分批读取、关闭读通知后再恢复，避免长时间后台运行卡死主线程（v1.7.7 现场问题）。

## 4. 局域网传输（`transfer/`）

接收方在 TCP 53318 运行 Dart `HttpServer`：

- `POST /v1/messages`：文字消息（JSON，最长 16000 字）。
- `POST /v1/transfers`：文件申请（发送方、文件名、大小、传输编号）。接收方按本机设置决定自动接收或弹窗询问，60 秒无人确认自动拒绝。
- `PUT /v1/transfers/{id}/content`：流式上传文件内容。接收方写入 `.part-<id>` 临时文件（每 16 MiB 落盘一次，有写盘背压），大小核对无误后原子改名；返回保存后的文件名。
- `DELETE /v1/transfers/{id}`：发送方停止，接收方删除未完成文件。

发送方每个文件分三个阶段（申请 / 传内容 / 等确认）。连接在答复前被断开时：还没开始传内容的自动重试 2 次；已经全部发出的提示“对方可能已经收到”，不自动重发（常见原因是 AdGuard 等软件接管连接）。文件名会清理路径分隔符和保留名，重名自动加序号。

## 5. 二维码配对通道（`pairing/`）

自动发现不可用时，一方显示二维码（地址、端口、配对码），另一方扫码或手动输入，建立 WebSocket 长连接 `GET /v1/pair/channel?code=…`（配对码不对直接拒绝）。文字和文件在这条通道里传输，界面称为“局域网安全连接”，保存后可自动重连。双方使用一致的规则选择保留哪条连接，避免交叉连接互相关闭；同一设备同时有直连路线时优先直连，失败回退到配对通道。

## 6. 公网中转（`packages/remote_protocol/`、`relay_server/`）

- 客户端只接受 `wss://` 地址。内容在客户端用“家庭加密口令”做 AES-GCM 端到端加密（加解密在后台 isolate 里进行），中转服务只看到设备 ID、时间和密文大小。
- 家庭口令和访问令牌只存在系统安全存储里，不发给 VPS、不写入普通设置。
- 单个文件最多 200 MiB，16 块流水发送，必须收到接收端“已处理”的确认才算送达（不把 VPS 接受当成送达）；可随时停止，接收端 45 秒无数据会清理。
- 中转服务不保存消息，收件人离线直接返回失败。服务端自 v1.7.2 起没有变化。

## 7. 聊天记录与离线排队（`chat/`）

- 聊天记录保存在本机（`chat_history_v1`，最多 1000 条），只增加过可选字段（送达状态、语音文字），旧记录照常读取。
- 离线排队：发给不在线或连不上的设备时，消息以“排队中”的聊天记录保存在发送方本机；对方再次出现时按顺序自动发出，每 30 秒重试。只有“连不上且一个字节都没发出”才排队，拒绝、取消、中途失败不排队。最多 100 条，7 天过期。
- 引用不改协议：按微信复制格式把“「名字：内容」+ 分隔线 + 回复”拼进文字，新版解析显示为引用框，旧版看到可读文字。
- 收文件确认由接收端本地决定（自动接收设置），“连接过的设备”只能由用户自己的操作加入。

## 8. 语音（`voice/`）

- 语音消息是 16 kHz 单声道 WAV 文件，文件名带时长（`语音消息_日期_时间_12s.wav`），走普通文件传输，不改协议；最长 60 秒。收发的语音都放在应用自己的 `voice_messages` 目录。
- 转文字和语音输入：sherpa-onnx + SenseVoice Small int8，在后台 isolate 里离线识别，模型加载一次、空闲 3 分钟释放。模型（约 229 MB）放在本仓库的预发布页 `asr-model-sensevoice-2024-07-17`，首次使用时下载，断点续传并核对 SHA-256。
- Windows 11 系统目录自带旧版 `onnxruntime.dll`，识别线程先从程序目录显式加载新版。

## 9. 缓存与清理

| 内容 | 位置 | 自动清理 | 用户操作 |
|---|---|---|---|
| 更新下载 | `update_cache` | 每次启动清空 | 设置可清空 |
| 粘贴的截图、转发复制的文件 | `outgoing_cache` | 启动时删 `.part`、30 天以上、超过 1 GB 的最旧部分 | 设置可清空 |
| 语音消息 | `voice_messages` | 启动时删录音残留、30 天以上、超过 500 MB 的最旧部分 | 设置可清空 |
| 语音识别模型 | `asr_model` | 启动时删 7 天以上的未完成下载和旧版本 | 设置可删除 |
| 诊断日志 | `diagnostics` | 1 MB 轮换，保留 7 天 | 设置可导出、清除 |
| 手机分享导入的文件 | 应用缓存 `shared-inbox` | 发送成功后删除 | 首页可放弃 |

Windows 下这些目录在应用数据目录（`%APPDATA%\com.personal.lantransfer\lan_transfer`）里，Android 在应用私有目录里。用户的文件（收到后保存到下载或自选文件夹的）不会被自动清理。

## 10. 更新（`update/`）

只读取 GitHub `releases/latest`（预发布、草稿和 `-rc` 不会推送）。下载附件后核对 GitHub 摘要和 `SHA256SUMS` 清单；Android 交给系统安装器（签名不同会被系统拒绝），Windows 由替换脚本关闭程序、备份、替换、失败还原并重新打开。下载走系统代理。

## 11. 网络兼容性

Windows 便携包附带 `enable_lan_access.cmd`，为当前 EXE 路径放行 UDP 53317 和 TCP 53318（公用、专用、域网络中的私有地址）。纯局域网模式无法解决：无线 AP 客户端隔离、VLAN 之间禁止互访、公司策略禁止入站连接、两台设备不在同一可路由网络——这些情况可以用自己的 VPS 中转。

## 未实现

- 设备公钥认证（目前设备 ID 自报）。
- 分块上传与中断后的断点续传（传输中断需要重新发送；只有语音模型下载支持断点续传）。
- 超过 200 MiB 的公网文件、公网点对点加速。
- 一次同时发给多台设备。
- 剪贴板同步；iOS、macOS、HarmonyOS、Web 客户端。
