# 第一阶段架构说明

## 1. 设计目标

应用只依赖当前局域网，不维护中心服务器。网络名称、网关和设备 IP 都是临时信息；应用只把本机生成的 `deviceId` 和密钥视为稳定身份。

设备切换网络后不会保留旧 IP 作为连接依据，而是监听网络变化，关闭失效连接，在新网络接口上重新广播并发现设备。

## 2. 设备身份

首次启动生成并持久化：

- `deviceId`：随机 UUID，不因改名或换网而变化。
- `displayName`：用户可修改，允许重名。
- `identityKey`：本机设备密钥，用于证明发现到的同名设备是否仍是原设备。
- `platform`：仅为 `android` 或 `windows`。

界面主要显示设备名称；发生重名时附加短设备 ID，例如 `会议室电脑 · A17C`。

## 3. 局域网发现

每个客户端同时监听和发送 UDP 广播。发现包只包含连接所需的最少信息：

```json
{
  "version": 1,
  "type": "announce",
  "deviceId": "uuid",
  "displayName": "书房电脑",
  "platform": "windows",
  "port": 53317,
  "nonce": "random-value",
  "signature": "base64-signature"
}
```

行为约定：

- 启动、改名和网络变化时立即广播。
- 在线期间以低频心跳维持可见状态。
- 同一个 `deviceId` 出现新 IP 时更新地址，不创建重复设备。
- 设备超时后标记离线，而不是删除历史和信任关系。
- 自动发现失败时允许显示本机二维码，由另一设备扫码取得局域网地址、端口和一次性配对令牌。

## 4. 信任与接收确认

局域网不是可信边界。首次收到陌生设备的发送请求时，接收方必须看到发送设备名称、文件名、数量和总大小，并选择接受或拒绝。

用户可以选择“记住此设备”。记住的是设备公钥指纹，不是名称或 IP。后续可以在设置中撤销信任。

文件名必须清理路径分隔符和保留名称，接收文件只能写入用户选择的接收目录，不能使用发送方提供的绝对路径。

## 5. 文件传输

接收方在局域网接口上运行本地 HTTP 服务。发送流程：

1. 创建传输任务，提交文件清单、大小和哈希。
2. 接收方提示用户确认。
3. 接收方返回任务 ID、分块大小和已经拥有的分块位图。
4. 发送方逐块上传，默认分块大小 8 MiB。
5. 每块完成后校验哈希并持久化进度。
6. 全部分块完成后校验完整文件并原子重命名为最终文件名。

初始接口：

- `POST /v1/transfers`：创建传输任务。
- `GET /v1/transfers/{id}`：查询状态和缺失分块。
- `PUT /v1/transfers/{id}/files/{fileId}/chunks/{index}`：上传分块。
- `POST /v1/transfers/{id}/complete`：请求最终校验。
- `POST /v1/transfers/{id}/cancel`：取消任务。

临时文件使用任务 ID 隔离。应用崩溃或短暂断网后，可通过缺失分块列表继续传输。

## 6. 换网行为

监听 Android 与 Windows 的网络接口变化。检测到变化后：

1. 停止向旧地址继续写入。
2. 保留本地传输任务、文件块记录和设备身份。
3. 在新接口重新绑定 UDP 和 HTTP 服务。
4. 重新广播本机并按 `deviceId` 合并发现结果。
5. 如果传输双方再次处于同一可达局域网，重新查询缺失分块并续传。

从公司切换到家庭网络时，公司局域网设备会离线，家庭局域网设备会出现；用户不需要选择“公司模式”或“家庭模式”。

## 7. 公司网络兼容性

为提高可用性，Windows 安装程序需要为应用的发现端口和传输端口创建作用域受限的防火墙规则。程序应监听所有有效局域网接口，而不是只选择第一个网卡。

仍然无法在纯局域网模式下解决：

- 无线 AP 客户端隔离。
- 不同 VLAN 之间禁止互访。
- 公司策略禁止入站连接或禁止未知应用。
- 两台设备实际上不在同一可路由网络。

这些环境将来只能通过公网中转、VPN 或由管理员配置网络规则解决。

## 8. 技术范围

- Flutter：Android 与 Windows UI 和主要业务逻辑。
- Dart `RawDatagramSocket`：UDP 广播发现。
- Dart `HttpServer` / `HttpClient`：局域网文件传输。
- 本地持久化：设备身份、信任列表、设置和传输任务。
- 系统文件选择器：选择发送文件和接收目录。
- Windows 托盘与通知、Android 分享入口：在基础传输稳定后加入。
