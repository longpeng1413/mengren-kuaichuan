# 猛人快传 v1.9.0 交接说明

## 版本与边界

- 版本 `1.9.0+32`，基于正式版 `v1.8.4`。局域网配对协议 2、公网协议 3、UDP 53317、TCP 53318、VPS、聊天存储格式、Windows 数据身份、单实例互斥名和 Android 签名均不变。接收确认是接收端本地决定的，发送端和协议都没动，旧版本之间仍可互传。
- 2026-11-05 用户实测电脑和手机双向自动接收通过，随后发布为 GitHub 最新正式版 `v1.9.0`。
- 用户 2026-11-05 要求：接收方在后台也能接收；局域网收文件不需要确认，中转模式普通文件和消息直接收发；或者做成设置项让用户选。用户选定：自动接收默认「只限连接过的设备」，后台持续接收默认关闭。

## 现状核对（改之前）

- 文字消息：局域网、配对通道、公网中转都直接接收，从来不需要确认。
- 公网中转文件：`_startRemoteFile` 直接开始写，没有确认框；单文件上限 200 MiB，所以「中转模式大于 200M 才确认」不存在。
- 只有局域网直连和局域网安全连接（`PairingRelay`）收文件会走 `_handleIncomingTransfer` 弹「接收文件？」，60 秒不点自动拒绝。
- Android 切到后台：`_pauseAndroidNetworkWork` 停掉局域网公告和重连定时器（电脑 7 秒后把手机判为离线），Activity `onStop` 释放组播锁；系统还可能冻结或结束进程。

## 设计

### 自动接收

- `AppSettings.autoAcceptMode`（`AutoAcceptMode.all/known/ask`，键 `settings_auto_accept_mode`，默认 `known`）。`shouldAutoAccept(mode, trusted:)` 在 `settings/trusted_devices.dart`。
- `_handleIncomingTransfer`：自动接收时直接 `_acceptIncomingTransfer`，日志 `incoming_transfer_auto_accepted mode=…`；手动点「接收」后 `_trustDevice(…, reason: 'accepted_file')`。
- 可信设备 `TrustedDeviceStore`（键 `trusted_device_ids`，最多 200 个，超出丢最旧的）。加入时机：`_sendText`、`_sendFiles`（选好文件后）、`_connectPairing`、`restoreRequests`（对方用本机配对码配对，配对通道本身要校验配对码）、手动接收。启动时 `_loadTrustedDevices` 把聊天记录里有 `isOutgoing` 消息的设备补进去。`_removeDevice` 一并删除。日志 `device_trusted peer=… reason=…`。
- 安全说明：局域网直连的发送方设备 ID 是自报的，而设备 ID 会在局域网 UDP 公告里公开，所以在不可信网络上「只限连接过的设备」可被冒充；配对通道有配对码校验，不受影响。设置弹窗和帮助里都建议公共 Wi-Fi 选「每次都询问」。

### 后台持续接收（Android）

- `AppSettings.androidBackgroundReceive`（键 `settings_android_background_receive`，默认 false）。
- 原生 `BackgroundReceiveService.kt`：`startForeground`（API 29+ 用 `FOREGROUND_SERVICE_TYPE_CONNECTED_DEVICE`，前置权限 `CHANGE_WIFI_MULTICAST_STATE` 已有），常驻低优先级通知；持有 `PARTIAL_WAKE_LOCK`、`WIFI_MODE_FULL_HIGH_PERF` Wi-Fi 锁和组播锁；`START_NOT_STICKY`。通知小图标 `res/drawable/ic_stat_receive.xml`。收到内容时 `notifyIncoming` 用另一个渠道发通知，点通知回到应用。
- `MainActivity.kt` 新通道 `com.personal.lantransfer.lan_transfer/background`：`start(askPermission)`、`stop`、`notify(title,text)`、`isIgnoringBatteryOptimizations`、`requestIgnoreBatteryOptimizations`。`popSystemNavigator` 在服务运行时 `moveTaskToBack(true)`（返回键不结束 Activity，否则 Flutter 引擎会销毁）；`onDestroy` 且 `isFinishing` 时停止服务。
- Manifest 新增 `FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_CONNECTED_DEVICE`、`POST_NOTIFICATIONS`、`WAKE_LOCK`、`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 和不导出的 `<service>`。
- Dart `background/background_receive.dart` 封装通道。`app.dart`：启动时 `_applyBackgroundReceive()`；设置开关变化时在 `didUpdateWidget` 里启动（带权限请求）或停止。`_keepsReceivingInBackground` 只在服务确实启动成功（`_backgroundServiceRunning`）时为真——`DiscoveryService.pause` 的注释说明，失去组播锁后继续广播会导致套接字重启循环。为真时 `_pauseAndroidNetworkWork` 不暂停发现和重连，`_shouldRunNetworkWork` 也返回真。`_appendChat` 对收到的内容在后台时调用 `_notifyIfInBackground`。
- 设置页开关打开后，若未忽略电池优化，弹窗引导「去允许」（`ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`），并提示魅族、小米需在系统里另外允许后台运行。
- 已知限制：从最近任务划掉、手机重启后不会自动恢复（Flutter 引擎跟 Activity 一起销毁，服务不自启）；耗电会增加（CPU 唤醒锁）。

## 构建环境变化（2026-11-05）

- 本机的 Visual Studio 2022 已不在（`C:\Program Files (x86)\Microsoft Visual Studio\2022` 为空），换成了 Visual Studio 2026 生成工具（`...\18\BuildTools`，MSVC 14.51）。首次编译报「CMake 生成器 Visual Studio 18 2026 与之前的 17 2022 不一致」：删除 `app/build/windows`（只是编译缓存）即可。
- 2026 生成工具缺少「C++ ATL」组件，`flutter_secure_storage_windows` 插件编译报 `atlstr.h` 找不到。经用户同意，用 `setup.exe modify --installPath "...\18\BuildTools" --add Microsoft.VisualStudio.Component.VC.ATL --passive --norestart` 补装（需管理员确认）。
- 新编译器编出的程序在系统 VC++ 运行库较旧的电脑上可能闪退，所以 `scripts/package_windows.ps1` 现在把 `msvcp140.dll`、`vcruntime140.dll`、`vcruntime140_1.dll` 从生成工具的 `VC\Redist\MSVC\*\x64\Microsoft.VC*.CRT` 复制进包（应用本地部署，找不到就报错停止）。ZIP 从 31 个条目变为 33 个（多 3 个 DLL，少了之前根目录的空 `native_assets.json`）。实测运行时三个 DLL 都从程序文件夹加载。
- 本机已按「固定文件夹原地升级」把 `dist\猛人快传` 升到 v1.9.0：标题 v1.9.0、TCP 53318 监听正常、未弹防火墙提示。
