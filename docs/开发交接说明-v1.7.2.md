## 问题证据

- 用户截图显示 Windows 向 Android 公网发送 60.8 MiB PDF 时约 `236.2 KiB/s`，并出现 `unknown_receipt`。
- Windows 诊断日志中 157 个 256 KiB 分块耗时 616 秒，原始数据平均约 `65.2 KiB/s`；相邻分块到达间隔 1.79–8.38 秒。
- Windows 对每块解密和写盘平均仅 30.9 毫秒，证明本地处理不是主要瓶颈。
- 同机经真实 VPS 往返 8 MiB 探针：4 块窗口约 0.72 MiB/s，16 块窗口约 1.73 MiB/s。

## 本次修复

- 公网文件窗口从 4 块扩大到 16 块，最多约 4 MiB 原始数据在途；没有采用 32 块，避免 Android 缓存和慢线路排队过大。
- 客户端回执等待由 25 秒提高到 90 秒；VPS 默认回执记录由 30 秒提高到 120 秒。
- VPS 对已超时或重复的回执仅记录 `late_receipt`，不再向接收端返回 `unknown_receipt`。
- v1.7.2 客户端也会忽略旧 VPS 返回的 `unknown_receipt`，避免误导性横幅。
- 新增 `MQT_RELAY_DELIVERY_TIMEOUT_SECONDS`，允许 30–600 秒配置；默认 120 秒。
- 新增 `packages/remote_protocol/tool/live_relay_throughput_probe.dart`，只使用临时设备 ID 和测试密钥，不读取聊天内容。

## VPS 部署要求

本次公网协议没有升级，但服务端行为有修改。私有验收 VPS 已更新为 `mengren-relay:1.7.2-ack120`，继续只绑定 `127.0.0.1:18080` 并复用 `/etc/mengren-relay.env`。未修改同机其他网站。

- 部署脚本：`scripts/deploy_relay_vps_v1.7.2.sh`。
- 部署前已备份容器配置并停止保留旧容器，可用于回滚；公开仓库不记录私有服务器的备份文件名。
- 新容器：`mengren-relay`，重启策略 `unless-stopped`，端口 `127.0.0.1:18080 -> 8080`。
- 私有验收环境的健康检查返回 HTTP 200 和 `{"ok":true}`；实际域名不写入公开仓库。
- 部署后双客户端发现、文字加密转发及文件开始/分块/结束生命周期验证通过；8 MiB、16 块窗口复测约 `1.73 MiB/s`。
