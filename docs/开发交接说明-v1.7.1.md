# 猛人快传 v1.7.1 开发交接说明

## 当前基线

- 当前版本：`1.7.1+14`，基于 GitHub `v1.7.0` 标签提交 `67bed01`。
- 修复分支：`codex/fix-v1.7.0-remote-progress-stability`。
- 局域网配对协议仍为 2，公网协议仍为 3；本次没有修改 VPS 线协议，不需要重新部署中转服务。

## 本次问题原因

1. v1.7.0 的公网文件每 256 KiB 都等待接收端完整处理回执后才继续，高延迟网络形成严格停等，吞吐受往返时延显著限制。
2. AES-GCM、PBKDF2、JSON 和双层 Base64 在 Flutter UI isolate 执行；Android 处理大文件时会阻塞渲染和点击事件。
3. 每个文件块在收发两端产生多次串行诊断日志写盘，并且进度没有限频，进一步增加主 isolate 和存储压力。
4. 接收端没有取消入口；发送端取消不能打断正在等待的单块回执；断线后未完成接收没有超时回收。

## v1.7.1 修复

- `RemoteCryptoWorker` 使用常驻 isolate 执行派生密钥、AES-GCM、JSON 和 Base64，派生密钥缓存不会因逐块任务丢失。
- 公网文件使用最多 4 个在途块的有限流水窗口；WebSocket 顺序和接收端串行处理继续保证块顺序。
- 发送与接收进度约 10 Hz 刷新，分块不再逐条写诊断日志。
- 接收端可点击停止，发送端收到取消后立即取消对应 token；发送端本机停止也可打断回执等待。
- 远程接收 45 秒无新块或连接断开时自动取消并删除临时目录。
- 接收写盘每 8 MiB `flush` 一次形成背压，限制 Android 内存排队。

## 必须实机验证

1. 手机与 Windows 都安装 v1.7.1，在不同网络下发送 100–200 MiB PDF/视频。
2. 确认手机发送端从 0% 开始显示百分比、进度和速度，点击停止后数秒内结束。
3. 在 Windows 接收端点击停止，确认手机发送端结束，Windows 进度消失且没有 `.part` 文件。
4. 传输中强制结束发送端，确认接收端在断线或最多 45 秒后清理进度和临时文件。
5. 长传输期间持续点击会话、返回、滚动和输入框，确认 Android 不再失去响应。
6. 对比 v1.7.0 与 v1.7.1 的公网速度；实际上限仍受手机上行、接收端下行、线路、TLS 和 VPS 带宽影响。
