# 猛人快传 v1.8.0 交接说明

## 版本与边界

- 版本 `1.8.0+27`，基于正式版 `v1.7.8`（`1.7.8+26`）。新增检查更新与一键自动更新（Android + Windows）。
- 局域网配对协议 2、公网协议 3、UDP 53317、TCP 53318、VPS、聊天存储、Windows 数据身份（CompanyName/ProductName）、单实例互斥名和 Android 签名均不变。
- 用户 2026-11-03 要求加入此功能，手机和电脑端都需要。本版尚未打正式标签、尚未发布 GitHub Release，等用户实机确认。

## 设计

- 更新源固定为 `https://api.github.com/repos/longpeng1413/mengren-kuaichuan/releases/latest`（只返回非草稿、非预发布的最新 Release）。标签必须是 `vX.Y.Z`，带 `-rc` 等后缀的一律忽略；只有严格更高的版本才提示。
- 附件命名必须保持：`mengren-transfer-android-vX.Y.Z.apk`、`mengren-transfer-windows-x64-vX.Y.Z.zip`、`SHA256SUMS-vX.Y.Z.txt`。**以后发布时改了命名，旧版本就找不到安装包。**
- 校验：GitHub 附件自带的 `digest`（sha256）与 `SHA256SUMS` 清单至少要有一份，两份都有时必须一致；下载时边写边算 SHA-256，不一致删除。只走 HTTPS，重定向到非 HTTPS 会拒绝。
- Windows 读取系统代理（注册表 `ProxyEnable`/`ProxyServer`），因为 Dart 的 HttpClient 默认不走系统代理；环境变量代理优先。
- 自动检查：启动 8 秒后一次，之后每 6 小时检查一次条件，但 24 小时内最多联网一次；Android 只在前台检查；「跳过此版本」只影响自动检查。失败静默，原因写诊断日志（`update_` 前缀）。
- **Android**：APK 下载到 `cacheDir/update_cache`，校验后通过 `PackageInstaller` 会话交给系统安装器；第一次需用户允许「安装未知应用」，从设置页返回后自动继续。安装结果由不导出的 `UpdateInstallReceiver` 接收，其他应用无法伪造确认窗口。系统会拒绝签名不同的 APK。
- **Windows**：ZIP 下载到 `%APPDATA%\com.personal.lantransfer\lan_transfer\update_cache`，应用仍在运行时先用 PowerShell 解压到 `staging-版本`，检查 `猛人快传.exe` 与 `data/app.so`。再由一个短暂的 PowerShell 用 `Start-Process -WindowStyle Hidden` 拉起独立运行的 `apply_update.ps1`；脚本先写 `apply_started.txt`，程序看到它才彻底退出（15 秒没看到就不退出，提示手动下载）。**不要改回 Dart 的 `ProcessStartMode.detached`：PowerShell 5.1 在这种无控制台模式下会立刻退出、什么都不执行。**脚本等待旧进程结束 → 备份将被覆盖的文件 → 覆盖（不删除文件夹中的其他文件）→ 失败则还原备份并删除新增文件 → 写 `update_result.json` → 重新启动同一路径的 EXE。路径不变，防火墙规则、开机自启和数据身份都不受影响。
- Windows 只在当前程序名为 `猛人快传.exe` 且程序文件夹可写时自动更新；否则提示手动下载（例如开发构建 `lan_transfer.exe`、放在 Program Files）。
- 清理：更新缓存在每次启动时整体清空（先读取上次 Windows 更新结果再删）；设置页显示占用并可一键清空（更新进行中拒绝清空）。下载中的 `.part` 在失败、取消、校验不符时立即删除。
- 「更新测试版」：编译时加 `--dart-define=MENGREN_UPDATE_TEST_CURRENT_VERSION=1.7.0`，标题带「更新测试版」，会把 GitHub 当前正式版当成新版本安装，用于在不发布新版的情况下实测整套流程。正式包不带此参数。Android 测试版用构建号 26，这样能覆盖已装的 1.7.8，也能被 1.7.8 再覆盖回来。

## 实测问题与修复（2026-11-03）

- 现象：用户用 Windows 更新测试版实测，能发现更新、能看到下载，下载完成后程序关闭，但没有替换、也没有自动重新打开（用户手动打开后仍是测试版）。
- 诊断：诊断日志显示 `update_download_verified` → `update_prepared` → `update_apply_launched` 都已出现，但下次启动没有 `update_previous_result`，更新缓存里也没有 `backup` 文件夹和 `update_result.json`，说明替换脚本完全没有执行。在临时目录复现：直接运行脚本正常；用 `ProcessStartMode.detached` 启动 PowerShell（无论是否带 `-WindowStyle Hidden`，连只写一个文件的命令也一样）都不执行就退出，`detachedWithStdio` 也没有任何输出；普通模式正常。
- 原因：Windows PowerShell 5.1 在 DETACHED_PROCESS（不分配控制台）下无法运行。原有测试用 `Process.run` 直接运行脚本，没有覆盖程序真实的启动方式。
- 修复：`launchWindowsApply` 改为中转启动并等待「已启动」标记（见上文设计）；参数用 `quoteWindowsArgument` 按 Windows 命令行规则加引号，再按 PowerShell 单引号规则转义。新增测试按程序真实方式启动替换（安装目录名含空格、中文、单引号）。版本号保持 1.8.0+27（尚未发布），安装包重新构建。
