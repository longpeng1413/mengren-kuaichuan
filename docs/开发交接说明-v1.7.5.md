## 当前基线

## 本次问题与原因

Android 实机日志来自魅族20（Android 16）。应用进入后台后，`activity_on_stop` 已释放 Wi-Fi multicast lock，但 Dart 层仍每两秒执行局域网广播和网卡枚举。网络切换或系统限制广播时，旧逻辑把“没有广播目标”当作 socket 损坏，随即每秒关闭、重建 UDP 53317 socket；同时配对和 VPS 仍继续自动重连。日志中可见重复的 `discovery_announce_failed`、`discovery_socket_started` 与 VPS DNS 失败。连续的 socket、网络枚举与诊断写入会挤占 Android UI isolate，符合用户回到前台后点击无响应的现象。Windows 没有这一 Android 后台生命周期，因此未出现同类问题。

## 本次修改

- `DiscoveryService` 新增暂停/恢复：后台取消发现、离线清理与绑定重试，并关闭 UDP socket；恢复时重新绑定并立即公告。
- UDP 广播没有可用目标时只记录跳过，不再销毁可复用 socket；socket 真正 `onError`/`onDone` 时改为单一、可取消的两秒重试，避免并发重建。
- `DeviceListPage` 仅在 Android 监听生命周期：后台停止配对/VPS 的周期重连，恢复时重启发现、恢复已保存配对并按需连接 VPS。既有会话不会被主动断开，避免后台时中止用户正在发送的文件。
- Android 原生网卡日志仅在接口快照变化时写入，仍保留网络变化诊断能力。
- 新增 `discovery_lifecycle_test.dart`，覆盖暂停后不会继续枚举网卡或发送公告。
