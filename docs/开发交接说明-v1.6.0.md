# 猛人快传 v1.6.0 开发交接说明

## 1. 项目目标与边界

“猛人快传”是 Android 与 Windows 之间的个人局域网传输工具，不依赖账号、公网服务器或云存储。

- 支持 Windows、Android；暂不支持苹果、华为鸿蒙独立客户端。
- 同一局域网内自动发现设备，也可通过二维码或手动输入 IP 配对。
- 支持文字、链接、图片、视频和任意大文件。
- 手机和笔记本移动到公司或家庭的新局域网后，会发现该网络内的设备。
- 纯局域网版本无法跨互联网访问留在另一地点的电脑。

- Android 包：`dist/猛人快传-android-v1.6.0.apk`

SHA-256：

## 3. 已实现功能

- 永久设备 ID、自定义设备名称。
- UDP 自动发现和设备离线检测。
- 二维码、IP、8 位配对码手动连接。
- 配对通道双向文字和文件传输。
- HTTP 局域网直传以及配对断开前的直连回退。
- 发送/接收百分比、进度条、速度和文件大小。
- 等待接收确认和传输过程中可由发送端停止。
- 取消后关闭接收确认框并删除未完成 `.part` 文件。
- Windows Enter 发送、Shift+Enter 换行、拖放文件。
- Android 系统分享、多个文件分享、微信“其他应用打开”。
- Android 接收文件写入系统下载或 SAF 自定义目录。
- 文件气泡点击打开，消息历史、清空缓存、移除设备。
- Windows 开机自启动、默认保存目录、关闭到托盘、单击托盘恢复、单实例。
- 浅色、深色、跟随系统模式和五种强调色。
- Android/Dart 双层诊断日志、导出、清除、1 MB 轮换、7 天自动清理。
- 大文件 1 MB 网络块、16 MB 写盘回压、约 10 Hz 进度刷新、WebSocket 关闭二次压缩。
- 聊天图片缩略解码，Flutter 图片缓存限制为 32 MB。

## 4. v1.6.0 重点修复

v1.5.0 实机曾出现手机与四屏台式机的扫码设备反复出现/消失、等待确认时报“配对连接已经断开”，但手机与笔记本正常。

定位并修复了两个源代码问题：

1. 两端同时恢复扫码连接时可能产生两条交叉 WebSocket，双方各自保留不同通道后互相关闭。v1.6.0 在 hello 中交换随机 nonce，双方用同一个 sessionKey 规则稳定保留同一条连接。
2. 聊天页原先保存进入页面时的连接类型，配对断开后仍可能使用旧路由。v1.6.0 每次发送前检查实时配对会话，并在文件尚未开始时回退到同设备的局域网直连。

新增集成测试覆盖同时双向重连、直连等待确认取消、配对等待确认取消。

## 5. 仍需实机验证

- 在家中让手机、四屏电脑、笔记本全部升级到 v1.6.0，再进行双向文字、小图片和大视频测试。
- 重点观察手机中的四屏电脑是否仍反复出现/消失。
- 分别测试等待确认时停止、传输到一半时停止，并确认接收端没有残留 `.part` 文件。
- 测试微信表格“其他应用打开”和系统相册分享。
- 测试 Android 深色主题、日志导出与清除。
- 原用户提供的 v1.5.0 日志附件在开发电脑所示路径中不存在，未能读取；如问题复现，请导出 v1.6.0 新日志。

## 6. 关键源文件

- `app/lib/main.dart`：启动、全局异常日志、图片缓存限制。
- `app/lib/src/app.dart`：设备列表、实时路由选择、收发业务、聊天入口。
- `app/lib/src/pairing/pairing_relay.dart`：配对协议、稳定连接选择、双向文件流。
- `app/lib/src/transfer/transfer_server.dart`：HTTP 接收、确认、取消和临时文件清理。
- `app/lib/src/transfer/transfer_client.dart`：HTTP 发送、进度和取消请求。
- `app/lib/src/transfer/transfer_models.dart`：传输请求、进度和取消令牌。
- `app/lib/src/chat/chat_page.dart`：聊天界面、进度和停止按钮。
- `app/lib/src/diagnostics/diagnostic_log_service.dart`：Dart 诊断日志。
- `app/lib/src/settings/`：主题、保存位置、自启动、诊断入口。
- `app/android/app/src/main/kotlin/com/personal/lantransfer/lan_transfer/MainActivity.kt`：Android 分享、ACTION_VIEW、MediaStore、原生日志。
- `app/android/app/src/main/AndroidManifest.xml`：Android 权限和 Intent 入口。
- `app/windows/runner/main.cpp`：Windows 单实例和窗口标题。
- `app/lib/src/desktop/desktop_tray_service.dart`：Windows 托盘。
- `app/test/`：15 项测试。

## 7. 开发与验证命令

项目原路径含中文，使用 `scripts/flutter.ps1` 临时映射 `L:`。运行前必须保证 `L:` 未被占用。

```powershell
.\scripts\flutter.ps1 analyze
.\scripts\flutter.ps1 test
.\scripts\flutter.ps1 build apk --release
.\scripts\flutter.ps1 build windows --release
```

构建输出：

- Android：`app/build/app/outputs/flutter-apk/app-release.apk`
- Windows：`app/build/windows/x64/runner/Release/`

发布前必须依次执行：格式化、analyze、全部测试、Android Release、Windows Release、APK 签名验证、Windows 单实例与 53318 监听验证。

## 9. Android 签名密钥

开发资料包的 `private-signing/debug.keystore` 是当前 APK 的更新签名，必须私密保存。丢失后，新 APK 无法覆盖手机已安装版本。

- alias：`androiddebugkey`
- store password：`android`
- key password：`android`
- SHA-256：`FE:1C:0C:49:65:D1:C2:9D:66:B6:EF:DE:11:F4:03:52:52:61:15:2A:B5:3E:18:E9:6A:B3:6F:EB:FE:49:54:64`

使用项目包装脚本时，将它恢复为：

`项目根目录/.tools/android-user-home/debug.keystore`

不要把完整开发资料包发到公开论坛、公开网盘链接或公共代码仓库。

## 10. Windows 发布注意事项

- Windows ZIP 必须包含 `lan_transfer.exe`、`data`、全部 DLL、`enable_lan_access.cmd/.ps1` 和说明文件。
- 用户必须完整解压，不能只复制 EXE。
- 新版本或移动安装目录后，以管理员身份运行一次 `enable_lan_access.cmd`；固定路径下重启无需重复运行。
- 升级前从旧版托盘菜单选择“彻底退出”，否则新快捷方式会恢复旧进程。
