# 猛人快传 v1.7.3 开发交接说明

## 当前基线

- 当前版本：`1.7.3+16`，基于公开仓库 `v1.7.2` 后续提交继续开发。
- 修复分支：`codex/fix-v1.7.1-relay-throughput`。
- 局域网配对协议仍为 2，公网协议仍为 3；新增的 `restoreDevice` 配对消息为可选消息，旧客户端会安全忽略。
- VPS 服务端继续使用 v1.7.2 的 120 秒回执容错版本，不需要重新部署或修改任何私有配置。

## 实机问题与根因

四屏 Windows 电脑使用网线，地址为 `192.168.0.65/23`、网关为 `192.168.1.1`。旧版只有 Android 原生网卡枚举；Windows 回退逻辑把所有普通局域网猜成 `/24`，因此将定向广播算成 `192.168.0.255`，而实际 `/23` 广播应为 `192.168.1.255`。Windows 防火墙已同时放行 Public 网络的 UDP 53317 和 TCP 53318，两个端口也在 `0.0.0.0` 正常监听，故不是网线或防火墙天然隔离。

魅族17不能在四屏电脑列表出现的直接原因是：电脑 `removed_device_ids` 中保留了该手机的稳定设备 ID。日志同时显示扫码后配对设备数从 2 增至 3、并成功收到魅族17文件；原代码仅在主动扫码的一方解除隐藏，被扫码的一方仍会在合并列表时永久过滤该 ID。

## 本次修复

- Windows Runner 新增与 Android 同名的平台通道方法，通过 `GetAdaptersAddresses` 返回活动 IPv4 网卡的名称、地址、`OnLinkPrefixLength` 和广播地址。
- Windows 构建链接 `iphlpapi` 与 `ws2_32`，Dart 网络服务在 Android 和 Windows 都优先使用原生真实前缀，失败时才回退。
- 手动扫码连接会发送经过配对通道认证的 `restoreDevice` 请求；接收端验证设备 ID 后清除对应隐藏记录。接受该设备新文件时也会恢复，兼容旧客户端。
- 设备合并改为直连覆盖二维码路线；发送时优先 HTTP 直连，如果尚未发送数据即连接失败且二维码会话仍在，则自动回退二维码通道。
- 已在四屏电脑本地只清除魅族17的隐藏 ID；聊天记录、VPS设置、设备身份和接收文件均未改动。
