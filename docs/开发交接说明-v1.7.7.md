## 故障现场与判断

用户提供了正在卡死的 Windows v1.7.6 进程。检查发现主线程持续运行并消耗 CPU，窗口无响应；日志最后记录网络恢复时 UDP socket 短时间重复启动、网络从无接口到临时地址的变化。

使用已有编译工具和 Windows DbgHelp，对主线程短暂暂停取样并立即恢复；通过匹配该 EXE 所用 Flutter DLL 的本地 PDB，定位到 `dart::bin::Builtin_Socket_RecvFrom` 与 `dart::bin::Builtin_Socket_AvailableDatagram`。没有导出内存、聊天内容或口令，也没有上传本机日志。

确认卡死发生在 UDP 读循环而非文件传输或托盘菜单本身。Dart UDP 可读通知通过微任务持续重发，旧代码没有暂时关闭通知或让出事件循环；并发绑定还可能覆盖当前 socket/subscription，旧监听回调却读取新 socket。窗口、托盘和网络处理共享执行资源，因而同时无响应。原始异常数据包无法追溯，不能断言唯一触发条件是空包；本次覆盖空读、持续数据、并发绑定及过期回调四类可导致空转的路径。

## 修改文件

- `app/lib/src/discovery/discovery_service.dart`：绑定单飞、生命周期 generation、回调绑定来源 socket；接收前关闭读通知、32 包批次上限、每批只发布一次设备列表，Timer 恢复；空读指数退避、8 次连续空读后关闭并延迟重建；关闭时先禁用读写通知，公告不能绕过重建冷却。
- `app/test/discovery_socket_test.dart`：11 项新增测试，包含真实 UDP 空包/无效包之后仍能发现设备，以及无 UI 活动超过七秒后仍保活旧设备并发现新设备。仅增加测试注入入口，不更改发现报文格式。

- `app/pubspec.yaml`、`app/lib/src/app_version.dart`、`app/windows/runner/main.cpp`：统一为 1.7.7 / 构建号 24。
