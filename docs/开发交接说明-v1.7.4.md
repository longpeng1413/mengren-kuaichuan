## 本次实机现象与结论

四屏电脑升级 v1.7.3 后，正确向 `192.168.1.255` 广播，但日志中没有收到新的 UDP 设备记录；魅族20、魅族17和笔记本先后主动建立了配对 WebSocket，因此列表均显示旧名称“二维码本地连接”。这些连接使用历史保存的本地配对信息自动恢复，确实只走局域网，但名称错误地暗示用户本次扫描了二维码。

对当前活动手机地址反向探测 TCP 53318 超时，说明该路由器或手机状态允许手机主动连接有线电脑，却未稳定允许电脑主动新建到手机的连接。因此不能把安全连接强行改成 HTTP 直连；保留双向 WebSocket 是正确兜底。

## 本次修改

- `DeviceConnectionMode.paired` 的显示名称改为“局域网安全连接”。
- 设置说明明确：保存过的安全连接会自动重连，不表示本次扫码，且不会经过 VPS。
- `RemovedDeviceStore` 在兼容旧 ID 列表的同时保存设备显示名称。
- 设置新增“已移除设备”区，可恢复单台或全部设备。
- 移除设备时根据真实配对会话断开连接，而不是依赖合并列表当前是否显示为配对路线。
- 自动广播不会擅自撤销用户的移除；设置恢复、重新扫码或接受该设备的新文件可以解除隐藏。
